# 随机展示媒体发布说明

1. 先执行同目录 `random_display_media.pgsql.sql`。该迁移只增加两列；锁等待超过 3 秒会失败并回滚，可重新执行。
2. 更新 Web、Publish、Account 及执行发送恢复的 Scheduler。不要长期混跑新旧发送代码；旧版本不会读取新的媒体选择快照。
3. 更新前端。继续沿用原有随机媒体 VIP 权益，免费版冻结规则不变。

`profile_state.random_media_config` 保存资料级配置：`enabled:null` 为自动模式（图片超过 10 张选 10 张），`true` 为手动随机（未指定数量时为 5），`false` 为全部图片。数量仅计算图片，不包含视频。

普通图片在随机模式下打乱顺序，必发图片全部保留并置后；无必发展示视频时选一个普通展示视频，有必发展示视频时保留全部必发视频。验证媒体不参与选择。

`tg_job.display_media_selection` 在外部发送前持久化选中的媒体 ID 及顺序。重试直接复用；资料配置或 VIP 状态改变不会重新选图。已存在发送 Attempt 或已确认展示阶段的历史任务，首次生成快照时沿用旧算法，避免恢复时改变旧相册映射。媒体缺失或快照写入失败时返回错误，不以重新随机选择替代。

回滚应用可以保留新增列。回滚旧发送代码前必须先排空/隔离新版本已经开始的任务，避免旧版本忽略选择快照。

本地 PostgreSQL 集成测试使用专用端口 55483 和一次性数据库集簇；不连接线上，不发送 Telegram 消息。
