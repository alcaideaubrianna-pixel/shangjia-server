# 扫图阈值 12 修复与验证（2026-10-18）

## 已确认原因

- 相册自动将距离阈值提高至 14，导致旧桶查询超时及无关图片被返回。
- PostgreSQL 线上缺少 `idx_ybp_phash_alias_search`；同一候选 SQL 补索引前约 9281ms，补齐后约 327ms。索引现已有效。
- 相册逐图重复加载资料详情、来源、标签、封面。
- 单图也进入 1500ms 静默窗口，轮询可能等待约 3 秒才开始搜索。
- 视频解析同时请求视频本体和缩略图的 getFile，尽管扫图只使用预览图。
- 下载使用较小图片版本的稳定 ID，不能对应发送记录保存的最大图片版本 ID。
- 防扫图指纹以固定历史键覆盖保存，后一次生成会覆盖前一次生成的指纹。

## 代码行为

Bot 图片、相册、视频预览图统一距离上限 12；先在权限范围内查询 Telegram 稳定媒体 ID，未命中才下载预览图并计算指纹。候选查询最多并发 2 个，相同指纹只查询一次，聚合后统一加载资料。单图直接搜索；相册静默窗口 300ms、轮询间隔 50ms。视频扫图只解析缩略图，缺失缩略图时明确报错。

生成指纹的持久化键包含生成版本哈希，后续版本不再覆盖旧版本；搜索缓存命名空间升级，避免沿用旧空结果。

## 生产数据修复范围

节点 `b-xiaohuiji-sg`，数据库 `railway`。租户 5、账户 6、资料 676231 的 18 条真实发送记录，对应 6 个媒体。

从发送记录关联的 Bot 读取 getFile，仅下载照片；视频本体未下载。下载得到的真实频道图片重新计算 pHash。修复前逐张回放有 5 张旧图片无结果。精确核对发送记录与媒体归属后，在事务中追加 72 个指纹桶，保留原有指纹；插入实际影响 72 行。追加使用确定性的版本键，同一批次重跑不重复插入。

回滚仅删除此次新增的版本键，不能按资料 ID 清空全部历史指纹。批次输入、核查及修复 SQL 位于执行机 `/tmp/youban-sent-fingerprint-*.sql`，包含此次精确版本键；不能将其作为其他资料的通用修复脚本。
