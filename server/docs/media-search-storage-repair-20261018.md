# 媒体搜索存储链路修复与本地验收

## 修复范围

沿用 `processMediaPipeline`，拒绝复用只有 MD5、没有有效 pHash 的图片/视频缓存。

原媒体插入、编辑及处理结果保存复用 `saveMediaDataAndIndex`，媒体行和搜索投影在同一事务写入。编辑后 pHash 尚未完成时清理旧源图索引，避免把旧指纹当成新文件。索引同步读取源媒体 MD5，修复之前投影中的 MD5 被写空的问题。

媒体任务不能只凭 ready + MD5 跳过：图片和视频还必须有有效 pHash；ready 重试继续同步索引、资料指纹和唤醒任务，不再因上次失败而永久漏掉索引。

采集媒体及其搜索桶/资料索引在同一事务提交；复用既有资料的重试也同步搜索投影。

防扫图轻量扰动、背景替换、文档跳过和生成文件复用的成功分支统一在返回上传文件前计算最终文件的指纹，按原媒体所属租户/账户/资料保存版本索引。四桶原子提交，版本追加、重复版本幂等；保存失败返回媒体准备错误，使用既有任务重试，不先发送后补救。发送回执只保留防扫图历史元数据，不再负责搜索指纹落库。视频仍只为预览图计算图片指纹。

## 现有数据：先审计索引，不下载全库

新增显式维护命令，默认只读、每次最多 1000 条、默认 100 条、最多执行 2 分钟。按媒体 ID 游标推进，可限定租户和资料；核对全部 16 个 nibble 桶、4 个 LSH 桶的值和归属，以及指纹投影的 MD5/pHash。不能仅凭桶数量判断健康。

```sh
./main up -m=fix -a1=mediaSearchIndexRepair -tenantId=5 -profileId=676231 -limit=100 -afterId=0
# 明确执行修复：
./main up -m=fix -a1=mediaSearchIndexRepair -tenantId=5 -profileId=676231 -limit=100 -afterId=0 -apply=1
```

下一批使用日志中的 `afterId`。单条失败返回错误和前一游标，原游标重跑幂等。修复复用运行时的索引同步方法，逐条同步后复核并刷新缓存版本，不触碰原图或防扫图历史版本。

没有合法源 pHash 的记录打印 `媒体指纹待补算`，计入 `needsFingerprint`，不会被误报为已修复。这类记录需要已有 `mediaPHashMissing` 命令读取存储文件补算；该命令仍是独立维护任务，不能在请求/启动时自动跑。此次限制视频候选为预览图，缺少预览图时不下载视频本体。

该命令不恢复已覆盖的防扫图历史版本、不修复资料权限或来源映射，不会自动创建数据库结构。历史版本需要现存生成文件或历史发送文件；不能从原图 pHash 反推出旧版本 pHash。新的版本存储修复无法自动补回已经丢失的数据。

## 本地验证方式

使用 127.0.0.1:35432 的 PostgreSQL 17，所有集成测试在事务内建立临时表；不连接生产数据库、不启动账号、不发送 Telegram 消息。

```sh
YOUBAN_SCAN_STORAGE_PG=1 go test ./addons/youban_publish/logic/sys ./internal/cmd/upgrade/fix \
  -run 'Test(MediaSearch|MediaPipelineCache|MediaProcessingReady|MissingMediaPHash)' -count=1
```

覆盖原媒体 MD5 传递、新增与编辑的事务回滚、编辑清空指纹时删除旧索引、ready 重试不跳过索引、生成版本共存与幂等、共享源归属、生成失败阻止上传并清理临时文件、四桶部分写入回滚、精确和距离 4 回退、跨租户隔离、无关输入不命中，以及修复命令 dry-run/游标/范围/损坏桶修复。

真实历史样本可额外指定 `YOUBAN_SCAN_FIXTURE_ROOT`；需要私有的 `search-snapshot.json`、`other-all`、`gvj-all` 和 18 张 `sent-tg` 图片，缺失样本必须失败，不能静默跳过。图片与数据快照不进入仓库。该回放覆盖本地 HTTP 下载、指纹计算、候选查询和相册聚合，不包含 Telegram getFile、消息接收/回复、完整资料详情渲染，也不代表全库规模性能。

本次不部署、不执行生产回填。首次完整查询 3 秒目标仍需要生产规模及真实 Telegram 链路验收，不能用本地小库耗时替代。

## 本次执行结果

- 本地 PostgreSQL 临时表集成、相关回归和 `-race` 均通过，CLI 包编译通过；补充的上传处理和采集校验回归通过。
- 私有快照限定为两份资料的 14 个有效媒体、136 个历史版本桶。三组历史输入（EEKFQFFA、JNAAUKWG、GVJFGVCU）和 18 张历史发送图片，共 21 个案例均在本地回放成功，聚合结果每例只含对应资料。
- 非竞态模式下，含本地 HTTP 下载、计算指纹和候选查询：首次 15.50–103.28ms，重复 0.007–0.056ms。这是小规模快照候选搜索耗时，不是线上全库或 Telegram 端到端耗时；历史样本包含之前已补齐的 18 张版本，不能据此宣称其他缺失版本已恢复。
- `go vet` 仍被既有的 `tg_message_repair.go:564` 不可达代码阻断，该文件本次未修改。不能将本次结果表述为全量测试或全部静态检查通过。
- 本地测试最初因替换全局配置适配器与文件缓存清理协程并发而触发竞态；测试已改为使用配置适配器的同步 setter，最终包含真实样本的相关 `-race` 检查通过。
