# 采集频道计数重构与生产验证

## 故障证据

2026-11-11 03:07:15 +08:00，traceID `8467afb8326b36e5df23c01f3b4c4c48`。
规则 338、账户 615、空关键词、includeCandidates=true、每页 20 条的列表请求，
耗时 3.13 秒后因应用设置的 3 秒截止时间取消历史统计 SQL。
SQL 同时读取频道归属索引、dispatch/event、TG job、profile_origin，再去重与校验资料归属。
生产执行计划中 TG job 分支扫描了不适合本查询前缀的历史索引，并有多层排序和关联。

## 实现

新增 count 和 count_member 两张内部投影表；member 引用数保证频道别名、重复写入、
多规则共用资料不会重复计数。rule_id=0 是跨规则去重视图。
数据库事务触发器覆盖新旧程序写入、资料删除/恢复、账户归属变化。
计数仅包含仍有效的资料与归属，下架操作不改变资料数量。

HTTP 计数只读取 ready 的频道计数。对缺少计数的频道才探测未回填索引，
未初始化返回明确错误，不伪装成 0，也不回退扫描历史表。
候选频道的资料索引读取也替换为计数表，保留真实 last_seen_at，防止显示迁移时间。
历史证据查询只留给下架范围校验、显式补全与测试使用。

脚本：`addons/youban_publish/resource/sql/collect_channel_counts.pgsql.sql`。
工具及发布顺序：`tools/collect_channel_counts/README.md`。

20,074 条历史关系，两个并发回填连接及八个重复写入连接。
验证频道别名、多规则、跨账户/租户、回滚、重复迁移、软删除、物理删除、
恢复、账户归属变化、历史补全和漂移审计。
汉庭线上元数据及 70 份资料索引验证两个列表分支、关键词搜索及未初始化错误。
下架历史范围、规则生命周期回归通过。

本地 20 个频道计数查询约 0.23～0.35ms，仅作本地性能记录，不等同生产 HTTP 耗时。

## 生产变更和核验

生产连接 PostgreSQL_Xiaohuiji/railway；迁移由现有 dbuser_dba 身份执行。
只新增计数结构、触发器和投影标记；既有资料没有删除或重放。
每批 200 行独立提交，远程命令超时后从未处理记录继续，未回退已完成批次。
大账户回填验证发现逐行初始化检查读取大量旧版本元组，已改为批量事务标记，
结束后按范围确认 ready；实时写入的计数增减仍在原事务中完成。
重复迁移使用 CREATE OR REPLACE FUNCTION 和条件创建触发器，避免反复删除忙表的触发器。

完成时的只读核验：

- 未回填记录 0，未 ready 计数 0，925 条频道/规则计数记录。
- 有效归属明细与全部计数对账：差异 0。
- 03:56:52 快照：93,073 条关系均已投影，87,705 条有效关系。
- member 引用数 175,410，等于两类规则视图所需的 2×87,705。
- 汉庭 tenant78/account615/rule338/channel4386299825：70 份、ready=true，
  last_seen_at 为 2026-11-11 01:35:30.587849。
- 故障请求同一页 20 个频道，在同一数据库快照比较历史统计与新计数：
  19 个非空频道全部一致，另一个频道双方均无资料；合计 10,067 份。
- 该页生产新计数 SQL 执行时间 41.582ms，属于数据库执行时间，不是 HTTP 总耗时。

此验证没有把其他缺失历史来源自动恢复：计数对账校验的是当前归属明细。
缺失历史明细需要用工具按精确账户、规则、频道预览并补全。

## 发布与回滚

数据库迁移、回填与对账已执行；Web 读取代码需构建后更新 web 角色才会生效。
不需要为计数改变 collector/publish 的工作职责。
回滚优先退回旧 Web 读取代码并保留兼容的计数结构。
触发器若需要停用，先回退读取代码，保留原资料与归属明细；重新启用前重建、对账计数。
