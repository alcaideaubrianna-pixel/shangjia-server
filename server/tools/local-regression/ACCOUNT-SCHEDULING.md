# 账户调度、迁移和本地运行验证

新引擎只以账户的 `push_engine=unified_stream` 为接管条件；全量 ENV 开关优先。不再要求同时维护第二个 `cycle_engine` 开关。

## 当前链路

Scheduler 每秒按主键分页读取账户目录，把账户调度任务交给已有 background 队列。每个账户独立租约、独立25秒执行预算；查询均限定 tenant/account。目录每页100个账户，账户总量很大时必须测量完整目录轮转延迟，不能承诺无限规模零延迟。

资料计划创建与准备统一复用既有 `YOUBAN_PUBLISH_CYCLE_ORCHESTRATOR_BATCH_SIZE` 配置（默认200），去掉单账户每次仅20份资料的额外限制；每阶段仍受2秒预算约束，超出本轮的工作保留持久状态供下一轮处理。

账户任务统一处理定时上架、长期不活跃免费频道限制、资料时间循环、批次循环创建和运行恢复/收尾。单个资料只创建一个循环run，选择本次已到期且可用的频道，源数据/状态准备一次，再拆为独立频道job。各频道的下一次循环时间仍按该频道配置计算；未到该频道的发布时间不提前执行。不同频道配置了不同发布时间时，不承诺同时发送；同一时刻到期的频道一起入队。

账户任务只产生并通知计划，不再在账户租约内串行准备全部资料。每个资料run作为独立Asynq任务交给background角色已有的资料维护队列，多个background节点可并行准备同一账户的不同资料；单份资料仍统一准备其到期频道。该队列与账户调度/状态投影分开，复用已有profileConcurrency（默认4），不再让大量循环准备挤占账户调度与状态投影。复用Asynq去重与25秒任务预算，SavePlan数据库行锁防止重复投递创建重复Job；待准备run本身是持久恢复依据，Redis通知丢失后由账户扫描重新投递。没有新增物理队列或部署角色；通用background队列保留同一handler用于兼容排空已入队任务。发布时必须先保证所有background消费者支持新任务类型，再切换计划生产者。

已排队/发送中/结果未知的频道不会再次创建循环任务，但同一资料的其他频道可以进入自己的下一轮。资料级run不是跨频道发送锁。成功频道提交自身结果后才检查run是否完成，避免并发提交互相看不到对方状态。

资料定时上架由已有 `publish_at` 字段承载。账户发送间隔仍复用已有 publish config、按频道记录的最后成功时间和共享缓存；修改配置必须经过已有配置保存接口，以主动清缓存。直接SQL改配置的测试显式调用相同缓存失效能力。

时间循环改由现有channel_profile映射的next_cycle_at索引选取计划，Job只按主键读取发送证据。领取计划时重读并锁定映射，推进映射的cycle_generation和重试时间，不再改写历史Job的dispatch_count。成功事件、配置重算同步维护映射计划；旧Job的next_cycle_at保留用于回退和审计。映射投影失败会由账户补偿修复。

发送成功状态、当前频道映射及旧到期计划失效在一个短数据库事务提交；事务内没有Redis或TG调用。新周期时间随后投影，空计划由账户补偿恢复。这样不会在Job已成功而映射仍保留旧到期时间的窗口重复领取。已确认发送仅本地提交失败时保留确认Attempt进入原对账链路，快速恢复扫描同时覆盖sending和具有确认检查点的unknown；未确认阶段不进入这条扫描，不能盲目重发。

批次循环保存频道cycle_round_end_id及每个批次upper_profile_id。整轮跨多个调度日保留固定上界，新资料进入下一轮；本轮结束后从头开始。每次只查询当前批数量，不再COUNT全部剩余资料。任务可靠生成后推进生产游标，发送终态仍按Job核验；部分失败不会被计为成功。旧批次upper_profile_id=0可继续完成，首次接管保留已有profile游标。

新引擎自动循环准备不再获取资料级Redis生命周期锁；复用任务工厂的事务幂等、资料行的短事务更新和发送前资料状态检查。手工编辑、下架等原有生命周期保护继续保留。实际用例持有旧资料锁时仍能创建新循环任务，并由真实发送节点完成；100频道批次共同翻新同一批旧资料另有压力覆盖。

账户补偿间隔10秒，优先检查最多200条当前映射的空计划，另按独立账户游标审计最多200条历史成功记录。历史查询先截取固定主键页再做完整性检查，避免“LIMIT200但实际遍历百万历史”的隐性开销；错误页也退避。只从真实成功记录补映射及计划，不恢复显式inactive映射、不伪造首次成功、不自动迁移到新的频道ID。历史频道被删后重建仍需既有映射迁移能力核验，不能仅凭频道用户名猜测归属。历史审计完成时间随账户历史量增长，灰度前应确认实际缺口收敛，不能承诺首次迁移瞬时完成。

免费循环复用ENV：YOUBAN_PUBLISH_CYCLE_FREE_INTERVAL_DAYS（默认15）、YOUBAN_PUBLISH_CYCLE_FREE_INACTIVE_DAYS（默认7）。闲置依据租户管理员最近后台活动，历史账户没有管理员时回退到本账户活动时间；仅关闭自动循环，手工发布及独立删除不受循环开关影响。会员过期后的批次降级继续复用已有配置重算。循环任务准备和实际发送前共用当前频道配置拦截；已有发送Attempt仍走原对账链路。

明确的Bot被踢、非成员、无发送权限立即复用频道熔断，写回失败Bot权限JSON，其他频道继续；chat not found仍使用连续失败阈值，网络超时、429、媒体错误不算失权。暂停只影响上架，不阻止发送证据收口和独立删除。恢复仍走既有权限检查入口。账户各调度阶段独立2秒预算，避免一个阶段耗尽整个账户25秒任务预算。

新手工/编辑操作保留新操作号和优先级，不复用另一操作的活动job；相同操作号重试幂等。正在执行或结果未知的任务不被强行抢占；频道下一条再选择优先级。旧操作的消息删除继续通过独立删除队列。

手工优先只绕过自动发布窗口，不绕过账户发送间隔。任务准备时也隔离频道错误：无效Bot等错误形成该频道独立failed任务，其他频道继续；部分失败不会被记为全部成功。同操作完成后再次提交不重开pending状态。

## 迁移顺序

1. 显式执行 `profile_cycle_orchestrator.pgsql.sql`（表不存在时）、`account_schedule_indexes.pgsql.sql` 和 `cycle_plan_runtime.pgsql.sql`；索引文件含CONCURRENTLY，不放在事务内。先升级字段再部署新代码；账户切换脚本会拒绝缺少计划字段的数据库。无需升级时全表回填，账户分页补偿渐进补齐计划；灰度前应观察计划缺口收敛。
2. 部署同一兼容版本到web、scheduler、background-worker和publish-worker。保留media角色现有媒体链路。按账户灰度时不要设置全量ENV，不关闭旧队列消费；publish-worker必须设置 `YOUBAN_PUBLISH_REDIS_STREAM_GRAY_ENABLED=true`，先开启Stream消费者再切账户字段。该开关不改变其他账户的引擎。相同配置项为 `youbanPublish.redisStream.grayEnabled`。
3. 用 `migrate-account-scheduler.sh tenant account` 默认只读查看设置、活动任务和到期计划。核对频道映射及历史计划完整性；本脚本不伪造历史成功时间，也不替换缺失映射。
4. 确认目标后加 `unified_stream --apply`。脚本在仍有running批次时拒绝切换，先等待该页生产结束。只修改一个账户设置；保留所有旧任务、消息证据、Outbox、批次游标和下一次循环时间。推送引擎缓存最长5分钟，等待缓存失效后再验收，不能把SQL成功当成各节点已切换。观察新run、频道任务、发送延迟及覆盖集合。
5. 逐账户放量。待旧队列和旧批次清空、回滚观察期通过，再删除旧扫描器及迁移兼容代码。当前保留旧代码用于回退，不再在全量新引擎正常路径运行旧全局分片扫描。

回退使用相同脚本的 `legacy --apply`，但必须保留兼容Worker完成已有新队列任务；禁止回退镜像后遗留无人消费的队列。全量ENV启用时，账户字段不能覆盖ENV，必须先调整部署配置。回退不删除、不重置、不盲目重发任何任务。迁移脚本输出原引擎供审计；凭据仅通过标准PG环境或PGPASSFILE提供。

回退前先停止目标账户的新计划生产，等待待准备profile run收口；脚本发现pending资料计划会拒绝回退。切换期间还需等待各节点引擎缓存失效，字段切换测试不能替代实际执行链路的热回滚验收。

## 真实本地运行

要求固定本地PG `youban_hotgo`、Redis 16382/DB15、TG Hook、2个publish-worker、background-worker、web和scheduler。按需包含media-worker。需要先导入完整本地资料/媒体夹具，按项目已有显式SQL补齐所需表结构。

```bash
bash server/tools/local-regression/run-business-scenarios.sh
bash server/tools/local-regression/run-runtime-scenarios.sh
bash server/tools/local-regression/run-runtime-faults.sh
bash server/tools/local-regression/run-cycle-load.sh
```

第一个脚本通过业务方法提交真实操作，实际Docker角色发送、接收Webhook、调度定时资料和循环批次。另含持续新增的三轮时间循环、批次固定上界与下一轮重头覆盖、缺失映射/计划修复、inactive保护、Hook真实403失权隔离及ENV免费保护。通过压缩落库到期时间模拟跨日推进，不是持续运行多天；不修改Job成功状态。第二个脚本验证1000普通发送、200迟到Webhook、300慢发送/删除隔离、720混合优先级任务。第三个脚本验证丢失就绪通知、实际重启专用Redis、强杀发送进程及Webhook确认续跑。历史压力报告基于当时版本，不能替代本轮新拦截与计划查询的复验。

这些场景使用本地完整夹具和已有导入结构，不证明最新生产全量数据均已回放；协议号降级、开启防扫图、Redis持久化文件损坏/完整数据丢失、所有历史脏映射和10K节点扩容仍需专项验证。Hook吞吐不是Telegram服务容量。不得把有限场景通过表述为所有情况绝对稳定。

本次共享任务工厂与生命周期有修改。最终发布应让已有web、scheduler、background-worker、publish-worker，以及参与任务生成/媒体续跑/Bot处理的collector-worker、collect-process-worker、media-worker、account角色使用同一代码版本。没有新增部署角色；是否实际启用这些角色仍按现有部署划分。上线灰度前保持旧队列消费者，不能只更新发送节点而保留旧任务工厂。
