# 采集查询减压边界

本文描述当前工作区重构的约束，不代表代码已提交、部署或通过线上验收。

## 正常路径

原始事件幂等落库 → 现有任务队列 → 来源/聊天批次 → 资料入库或审核 → dispatch 交接。
后续 TG Job 执行、发送和结果对账由现有发布模块负责。

- 批次按 tenant/account/source/chat 隔离；配对依照源消息顺序。
- 待处理版本变化表示有新工作；完成标记只覆盖本批实际访问的事件。
- 执行租约带归属凭证；租约丢失不能确认本批完成。
- 旧任务、未被当前批次覆盖的任务仍保留自己的持久化唤醒。
- Redis 故障返回可重试错误，不能让所有事件同时退回来源范围查询。

## 配对与回看

分类沿用现有规则。本轮性能重构不能放宽“一份展示仅匹配紧随的一组验证”。
同一视频组有多个视频不等于多个验证组；新的展示资料终止旧资料上下文。

数据库回看必须携带租户、账户、来源、聊天和消息边界，使用有界分页及超时。
分页截断表示尚未完成查询，不能标记为“没有展示资料”。
重复消费与并发绑定需要幂等；父展示行锁下检查已有验证关系。

## 恢复路径

- 自动恢复只处理已经登记的来源范围，不读取全局历史事件候选。
- 来源使用 Redis 持久游标轮转；查询、处理和投递均有独立数量或时间预算。
- Delivery 恢复按来源与实时/历史类别推进分页，避免反复投递同一批队头。
- 旧全局恢复不再能通过 ENV 接回自动主循环。
- 来源登记缺失时，使用明确的来源清单修复登记，不能以扫描整个事件表重建。
- 旧 PostgreSQL ingest spool 仅在明确启用该模式时按来源恢复。

## 账户任务

每账户由一个领取循环批量领取，交给现有并发执行 Worker。
领取保留数据库条件更新和租约 fencing，Redis 仅提供候选及空闲唤醒。
空闲等待有上限，Redis 丢失、延迟任务到期或丢唤醒后仍有账户级数据库兜底。
批量领取中途失败，已领取的任务必须继续交给执行端，不能丢弃已有租约。

维护接口必须显式指定账户。自动维护轮转已登记账户，每批最多 4 个，
每账户 5 秒预算；登记范围独立于在线 Worker，停止自动全局状态聚合。媒体下载任务还需覆盖该账户作为
`media_owner_account_id` 的情况，不能要求原账户上线才恢复任务。
Redis 不可用时仅回退本地已知账户范围；历史未登记账户需要显式、有界地重新登记。
预算结束后不再启动新的失败收尾，已开始的回调保留独立超时和并发槽。

GoFrame 的 `Scan` 使用实体/结构体接收候选，再提取 ID；维护函数不得依赖
把单列记录直接扫描进 `[]int64` 的未验证转换行为。

## 发布前核对

新增索引脚本单独评审并执行，不放进应用启动钩子。先核验现有索引及来源级执行计划，
再决定是否执行 `CREATE INDEX CONCURRENTLY`；`LIMIT` 本身不能证明扫描量小。

本地验证串行执行，Go 构建使用 `-p 1`，限制 `GOMAXPROCS` 与编译内存预算，
避免多个 agent 同时编译大包。验证应覆盖缓存故障、批次溢出、乱序回调、
绑定幂等、处理中新增消息、恢复公平性及批量领取部分成功；并发数据库绑定仍需
独立验收。分别记录代码、构建、部署和业务验收状态，不能以静态 review 替代测试。

线上对比使用相同长度时间窗口的 pg_stat_statements 增量，观察调用次数、
执行时间和读取块；累计历史 Top 不能直接证明新版本仍有相同调用。
业务验收同时核对 event 入库、资料入库/审核与 dispatch 交接，不能只看发送日志。

## 本轮验证记录

2026-11-17 本地串行验证已通过：Collector 全套测试、缓存及 Redis 轮转 race 测试、
资料窗口/配对/批处理专项、架构 guard 自测及全包构建。
独立 Docker PostgreSQL 测试覆盖账户维护隔离和媒体归属恢复、Event/Delivery
游标分页、跨页资料绑定及幂等、较短聊天 ID 与迟到媒体存在性查询。
临时 PostgreSQL 容器已停止；没有使用生产 DSN，也没有启动生产消费者。

全工作区架构 guard 扫描仍失败，涉及另外的 Publish 交接状态写入与
`singleflight.Do` 误报，详见本轮检查输出；本轮未修改 guard 或放宽基线。
以上通过项不能代替部署后真实采集入库验收，也不能推算线上 CPU 降幅。

## 提交前 Review 修正

- 后续新消息不再反复重置验证回看的分页位置；找到候选后在有限消息区间内重新核验。
- 验证事件锁定后检查文案、媒体、关系状态和微秒时间版本，旧分类快照只能重试。
- 错误父关系仅在原资料未处理、无入库来源、无分发和其他验证子事件时允许事务重绑；
  已产生下游资料的关系明确返回修复错误，不能静默覆盖。
- 离线账户继续通过维护登记参与轮转，避免任务失去恢复入口。
- 取消发生在批量领取与分发之间时，未分发任务按未开始执行归还，避免等待完整租约。
