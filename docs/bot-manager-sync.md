# 上架频道机器人同步

机器人管理展示的是可管理上架频道中的机器人，不是账户创建或保存 Token 的机器人清单。
同步读取频道管理员和机器人列表，分页完整后在事务中保存机器人及频道关系。
人工管理员计入频道管理员数量，不混入机器人列表。同步失败或分页缺失时保留原有成员关系。

首次打开及查询缺失的频道关系时提交持久化同步任务；同一账户同时只有一批同步任务。
提交后立即反馈频道数量；整批完成后通知成功/失败数量、机器人数量，并返回列表。
任务结果页、删除上架配置和详情中的更新 Token 入口已移除。任务记录仍用于后台执行、
恢复和通知，不删除正在执行的任务。

管理已经在频道中的机器人权限不需要 Token。添加发送机器人仍需凭据，且不改变已有
频道发送保护、任务顺序或 Token 归属约束。同步不会把第三方机器人自动绑定为发送机器人。

## 2026-10-21 同步不执行

生产只读查询发现 22 条同步任务为 `pending`、`account_task_id=0`；Account SLS 日志为
`不支持的Telegram账号任务类型：bot_manager`。消费者已注册，但正式提交入口遗漏此类型。
修复提交校验，并新增自动遍历声明类型的校验测试，避免新增类型再次遗漏。

部署角色：Web（菜单/回调）和 Account（调度、协议执行、通知）。无需数据库迁移。
未过期 pending 任务由原维护循环继续调度；已经超时失败的批次通过“同步机器人”重试。
Account 维持单实例，按既有发布方式切换。

本地回归使用隔离 PostgreSQL 数据库，包括真实 Account Submit 落库、空关系同步去重、
无 Token 机器人列表和权限修改、分页完整性、部分失败保留、通知与原有管理安全测试。
不通过生产 Telegram RPC 验证，不向真实用户发送测试通知。
