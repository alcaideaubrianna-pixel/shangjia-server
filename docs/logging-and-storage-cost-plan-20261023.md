# 日志降噪、公网归因及 OSS 迁移成本

日期：2026-10-23。线上只读核对；本次未部署、未购买服务器、未修改存储驱动或 SLS 采集配置。

## 已实现的降噪

- Publish：成功阶段 start/end 按 executionId 固定抽样约1%，同一次执行的所有阶段采用相同选择。错误、slow、panic 和最终 execution summary 不采样；阶段计时仍完整累计。`YOUBAN_PUBLISH_VERBOSE_TRACE=1` 可临时恢复全量成功阶段日志，排查后移除。
- Media：stdout 的正常采集进度按 eventId 抽样1%，失败进度始终输出 Warning。现有 DB 事件进度记录及后台进度查询保持完整。`YOUBAN_MEDIA_VERBOSE_PROGRESS=1` 可临时恢复全量进度。没有引入额外日志表或缓存。
- 镜像使用的 `manifest/config/config.example.yaml` 默认级别从 all 调整为 info，保留 INFO/NOTICE/WARNING/ERROR/CRITICAL。Dockerfile 会复制该文件作为镜像配置并打包。自定义配置文件或 `GF_LOGGER_LEVEL`、`YOUBAN_LOG_LEVEL`、`LOG_LEVEL` 可以覆盖，部署时需检查。
- 当前 Media、Publish 都仍启用 stdout SLS；只读查询未发现上述全局日志级别 ENV。这不是已经完成线上降费的声明。

验证涵盖抽样比例及执行一致性、诊断覆盖开关、成功阶段降噪、完整计时、错误/慢阶段/panic/汇总保留，以及 panic 继续向业务传播。

## Media 是否需要 SLS

建议保留精简日志：任务最终失败、下载重试耗尽、外部依赖错误、慢任务、队列恢复异常需要集中检索，DB进度不能替代进程崩溃和依赖错误日志。成功步骤不必逐条入 SLS。先部署降噪并观察一个完整自然日，再用写入账单和实际追踪可用性判断是否继续停采。

七日账单：全部 SLS 258.41GB / $15.76；Media $10.12、Publish $4.57，简单30日外推分别约$43.38、$19.58，合计全部角色约$67.56。不能将短时500条样本的正文构成直接当成整月节省比例。缩短保留期不能消除写入费用。

## $8 自建日志服务器

可以评估单节点日志存储，但先降噪再决定。单台服务器的购买价格不是总成本，还包含磁盘、网络、备份和维护。原始量约36.9GB/日，三天约110.7GB（未压缩），常见小磁盘套餐不能直接承接；压缩比需用实际日志测试，不能预设。

- 只有同地域、可互通的阿里云VPC才是此处可用的内网路径；同地域其他云厂商或普通公网VPS不自动具备内网。跨公网需认证、加密及核对出网费。
- 若将约1.1TB/月日志未经压缩直接通过EIP发往外部服务器，按当前边际$0.081/GB约$90/月，仅作量级示例，不能承诺比SLS便宜。压缩后费用应按实测字节核算。
- 应复用现有可观测性组件或选择单节点实现，部署前验证SAE的采集方式、可访问性与负载；本次未选购或安装新的日志系统。
- 日志发送必须异步、批量、压缩，缓存和磁盘有明确上限；日志端故障不能阻塞任务发送或将队列无限写入Redis。优先保留失败/慢任务，低价值成功日志允许采样丢弃，并暴露丢弃计数。
- 设置3天保留、磁盘水位和清理机制；不与生产DB共用紧张磁盘。单节点宕机意味着集中日志暂不可查，需要接受这一可用性边界。
- 精简后如果SLS本身已接近或低于$8/月，没有必要为了省钱再增加一台服务器。

## 公网详细归因方案

现有EIP角色指标只能定位角色，不能分辨目的地；部署会复用EIP，历史映射需要按时间保存。最近一小时角色占比不能代表整周。

第一层：CMS保留各实际实例/EIP的tx、rx，与账单同一窗口核对。SLB、公网对象存储的流量另计，不能合并为EIP一种费用。

第二层：应用传输统计按固定目的地组（Telegram Bot API、Telegram文件下载、自建Bot API、COS、CDN、OSS、其他）及操作（下载、上传）聚合。HTTP层统计请求体/响应体实际读取字节，包括失败和部分传输；记录请求数、失败数、重试、耗时、file_id/URL/二进制路径、缓存命中。每60秒每组输出一条汇总，不新增DB表、不逐文件输出日志。HTTP正文计数不等同TCP/TLS全部字节，须与CMS差额核对；协议号MTProto及DB/Redis流量另外统计。

第三层：同一媒体重复下载/处理/上传的排查复用现有mediaId、fingerprint、cache_hit及重试信息。媒体ID、用户ID、完整URL不得作为长期指标标签，避免高基数和敏感信息；按阶段区分必要的原图/处理结果上传，避免误判为重复。

第四层：只有应用统计无法解释的差额，才考虑短时有界流量诊断或VPC流日志，并先核对支持范围与新增费用。不默认开启长期全量流日志，也不通过EIP流量直接猜测上传占比。

按24小时输出：各目的地上下行GB、有效上传和重试GB、file_id/URL/二进制次数、缓存命中、可避免重复传输字节。字节计数全量聚合，成功链路细节抽样；抽样次数不能替代全量字节。

## COS → 同地域 OSS：哪些能省

| 路径 | 当前与迁移后差异 |
|---|---|
| SAE上传COS → SAE内网上传OSS | 可减少对应SAE EIP出站；OSS内网上传流量免费，仍有请求和存储费 |
| COS/CDN下载到SAE → OSS内网下载到SAE | 可减少原COS/CDN对应出站费用；SAE下载入站本来就不是主要EIP出站计费项 |
| SAE上传Telegram二进制 | 迁移存储不消除该EIP出站 |
| Telegram拉取媒体URL | 改由OSS公网出站或CDN计费，不能给Telegram内网URL |
| 同Bot有效file_id复用 | 不需要重新上传媒体正文，仍应优先复用 |
| 用户浏览/下载 | 仍有OSS公网/CDN费用，需比较两家实际单价与命中率 |

服务器SDK读写Endpoint与对外访问URL必须分开；新加坡同地域内网Endpoint需在SAE实际验证，已有对象URL、签名、缓存、缩略图和历史资料继续兼容。不能把公网URL整体替换为内网URL。

成本公式（统一GB口径和实际折扣）：

`净节省 = 避免的SAE→COS EIP费 + 避免的COS/CDN→SAE出站费 + 旧存储/请求费 - 新OSS存储/请求费 - 新OSS/CDN公网分发费 - 迁移期新增费用`

当前EIP超包边际价$0.081/GB，包余额为0。每避免1000GB服务器上传COS，可减少约$81 EIP费用；如后续包内边际成本改为$65/1024GB，约为$63.48/1000GB。不能把两种优惠重复累计。

按七日EIP全部出站外推约3885.6GB/月，仅给条件情景：

| 经统计确认可内网化的出站比例 | 可避免GB/月 | 按当前超包价减少EIP费 |
|---|---:|---:|
| 10% | 388.6 | $31.47/月 |
| 20% | 777.1 | $62.95/月 |
| 30% | 1165.7 | $94.42/月 |

这些比例不是实测COS上传比例，也不是净节省承诺。尚缺COS/CDN实际账单、存量容量、完整24小时目的地字节、新加坡OSS账户结算单价，当前无法给出可信的单一净节省金额。新OSS公网单价不应默认低于COS或EIP，需按实际地域及资源包报价比较。迁移旧数据还会产生一次性COS出站、双份存储和请求费用。

代码迁移前置问题：`media_direct_upload.go` 当前直传仅允许COS/R2；`anti_scan_aliyun_matting.go` 和 `anti_scan_cos_matting.go` 存在COS驱动依赖。通用OSS上传驱动不代表所有媒体功能都已兼容OSS。需要先适配直传、防扫图、Worker内网读写与对外URL，再做测试Bot小批验证和新写入灰度，旧数据后迁。
