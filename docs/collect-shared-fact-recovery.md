# 共享频道事实的定向采集恢复

频道消息事实按 `chat_id + message_id` 全局去重。记录上的
`tenant_id / received_bot_id` 只是被保留的接收方，不代表该频道消息只属于此租户。
不能据此筛选其他已获频道授权的采集源的完整消息范围。

## 恢复边界

1. 先验证目标租户、账号、采集源、规则与实际源频道的当前授权。
2. 只按用户明确批准的频道和消息区间查共享事实，禁止全局扫描。
3. 不复制其他 Bot 的 `file_id/update_id` 到目标 Bot。Bot 绑定的凭据
   与共享消息身份分开处理。
4. 本次只复用精确源频道、消息号、分组及正文一致的已落盘媒体；
   不从不同资料推测关联，不修改其他租户的业务事件。
5. 定向 SQL 同一事务锁定父事件，校验已有分发资料、精确媒体数量与
   验证父子关系，补齐缺失事件及媒体。任何断言失败整批回滚。
6. 提交后通过 MCP `requeue_events` 走正常采集入库和替换发布。
   入队、资料入库、TG API 成功需要分别验收。

## 防止部分重放

指定频道及消息起止号的 `replay_bot_source_updates` 预演，在完成频道授权后，
对比目标 Collector 候选消息与区间内的共享媒体事实。
缺少任何已知媒体消息时拒绝部分重放，提示首个缺失消息号，并记录
`collect.replay.incomplete`，含 source、频道、区间、候选数量和缺失消息号。
最多记录 50 个消息号，不记录 Token、文件 ID 或媒体 URL。

该检查只用于显式区间恢复，不增加实时任务查询或后台全局扫描。
它不证明 Telegram 发送过的所有消息均已接收，也不自动导入其他 Bot 的凭据。
